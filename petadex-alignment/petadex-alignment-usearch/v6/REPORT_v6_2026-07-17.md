# PETadex v6 — Results (flat 489-node partition, PL-identified)

Re-runs the [[PETadex v2 — Component Assignment Workflow]] Steps 0–3 on the new
`cleaned_pazy_final.tsv` (dropped in `petadex-alignment/data/`). Same paper-faithful method
as v4/v5 (usearch v11.0.667 `-allpairs_local`, permissive search + `≥30% aaid AND e<1e−5`
post-filter, single-linkage components). Flat de-novo, no v1 anchor.

## What changed vs v5

| | v5 (`cleaned_pazy_final.csv`) | v6 (`cleaned_pazy_final.tsv`) |
|---|---|---|
| Format | CSV, 4 cols | **TSV, 6 cols** (adds `identifier`, `pazy_id`) |
| Source rows | 500 (4 blank-seq) | **499** (0 blank-seq) |
| Node label | accession, fall back to enzyme name | **stable `PL<n>` identifier** (unique, always present) |
| Nodes (md5-unique) | 489 | **489** |

The new TSV carries the **exact same 489 unique sequences** as v5 (100% md5 overlap, verified),
so this is not a new biological input — it is the **same set with a cleaner, PL-identified,
deduplicated schema**. The value-add: every node now has a stable, unique `PL<n>` identifier
and a `pazy_id`, so the canonical component label is the PL id (v5 had to work around 26
blank-accession rows by falling back to enzyme names; that hazard is gone).

**The v6 partition is a byte-identical clustering to v5** (same 46 components, same membership,
verified by grouping nodes on md5). Component IDs are re-lettered because v6 orders components by
smallest PL number instead of smallest accession — the clusters themselves are unchanged.
