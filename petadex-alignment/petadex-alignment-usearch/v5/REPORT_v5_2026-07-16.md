# PETadex v5 — Results (flat 489-node partition)

Re-runs the [[PETadex v2 — Component Assignment Workflow]] Steps 0–3 on the **updated**
`cleaned_pazy_final` CSV (the two files dropped in `petadex-alignment/data/`). Same
paper-faithful method as v4 (usearch v11.0.667 `-allpairs_local`, permissive search +
`≥30% aaid AND e<1e−5` post-filter, single-linkage components); only the input data and
two robustness fixes differ. Flat de-novo, no v1 anchor.

## What changed vs v4

| | v4 (`plasticome.v2.cleaned_plasticome_final`) | v5 (updated `cleaned_pazy_final`) |
|---|---|---|
| Source rows | 476 (pre-deduplicated) | **500** |
| Blank-sequence rows | 0 | **4** dropped (TEP037, UMG-SP-1/2/3 — no sequence to align) |
| md5-duplicate rows | 0 | **7** collapsed across **6** md5 groups (e.g. Cut1/Tfu_0882) |
| Nodes (md5-unique) | 476 | **489** |
| v1 overlay source | `v2/canonical_nodes.tsv` | the updated `plasticome_v1.csv` directly |

Two new data conditions the v4 code did not face, both handled paper-faithfully (md5 = node
identity):
1. **md5-duplicate rows** — collapsed to one node; all contributing accessions / enzyme names
   preserved in `accession_all` / `enzyme_name_all`. Rows like Cut1 (`AET05798.1`) and
   Tfu_0882 (`AAZ54920.1`) are the *same* sequence → one node.
2. **27 rows carry an enzyme name but no accession.** The empty accession sorted *first* under
   v4's `min(accession)` canonical rule, blanking the label of the components those nodes
   anchor (including the giant one). Fixed: blank accessions now sort **last** and fall back to
   the enzyme name for the canonical label. **The partition is unchanged** — single-linkage
   components are accession-independent; only component IDs / labels are affected.
